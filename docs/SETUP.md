Рабочий адрес: https://azamatyessimkhanily.github.io/WEDX/

21.10.2026 подключён проект Supabase **WEDX** (`lhwvpjaatsroijgozoro`) в организации **WEDX Personal**, тариф Free, регион Singapore. Применена миграция, развёрнута функция `health-import`, настроены Auth URL, локальное окружение и переменные GitHub Actions. MCP `wedx-supabase` подключён к этому проекту для дальнейших изменений.

История из прежнего GitHub Gist перенесена в личный аккаунт: 134 записи упражнений. Полное состояние проверено чтением обратно из базы. Исходный файл сохранён в `.local/phone-backup-2026-10-21.json` и исключён из Git. Первоначальные данные владельца хранятся только на этом Mac в `.local/Доступ-WEDX.txt`. В интерфейсе больше нет email, пароля, регистрации и кнопки выхода.

WEDX теперь собирается как приложение. Открывать исходный `index.html` двойным щелчком больше не нужно.

```sh
npm ci
npm run dev
```

Адрес локальной разработки: `http://127.0.0.1:5173`. Нужен Node.js 22.12+; для CI используется Node.js 24. Без Supabase работают тренировки, прогресс, JSON-копии и локальное сохранение. Подключение устройства доступно после настройки проекта.

## Повторение настройки для нового проекта

1. Создать проект в организации на тарифе **Free**. Не выбирать платные дополнения.
2. Применить SQL-файлы из `supabase/migrations/` в порядке имени через SQL Editor в **новом проекте**. Они создают таблицы, ограничения доступа и функции записи. Через CLI вместо SQL Editor можно выполнить `supabase link --project-ref <ref>` и `supabase db push`.
3. Скопировать `.env.example` в `.env.local`. Указать Project URL и **publishable key** (допустим прежний `anon` key). `service_role` и пароль БД в приложение не вставлять.
4. В Authentication → URL Configuration указать адрес приложения в Site URL и Redirect URLs. Для разработки добавить `http://127.0.0.1:5173/`; для прежнего адреса — `https://azamatyessimkhanily.github.io/WEDX/`.
5. Создать владельца в Supabase Authentication и подключить устройство личной ссылкой, как описано ниже. Существующего владельца повторно создавать не нужно.
6. Перезапустить `npm run dev` после изменения `.env.local`.

URL и publishable key предназначены для клиента. Доступ к данным защищают проверка пользователя, RLS и функции БД, а не сокрытие публичного ключа.

Проверенные на 21.10.2026 условия Free: 500 МБ базы, два активных бесплатных проекта, приостановка после недели неактивности. Условия могут изменяться: https://supabase.com/pricing. Для этого приложения не требуется платная подписка. Если проект приостановлен, возобновить его в Dashboard; локальные тренировки затем синхронизируются.

## Личный режим и подключение устройства

Сохранённая сессия владельца восстанавливается автоматически и обновляется через refresh token. Устройство, на котором уже был выполнен вход, продолжит работать без нового подключения. Обычный публичный адрес приложения не содержит учётных данных и не открывает облачную историю без сессии.

Для нового устройства администратор выпускает одноразовую ссылку. В серверном окружении задать `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `WEDX_OWNER_ID` и `WEDX_APP_URL` (рабочий HTTPS-адрес WEDX), затем выполнить:

```sh
npm run device-link
```

Команда проверяет существующего владельца, вызывает Supabase Admin `generateLink` и сохраняет личную ссылку только в `.local/device-link.txt` с правами 0600. Письма не отправляются. Сервисный ключ не использовать в переменных `VITE_`, публичной сборке или GitHub Pages.

На телефоне открыть эту ссылку в нужном браузере и нажать «Подключить это устройство». Секрет ссылки передаётся в URL-фрагменте, удаляется из адресной строки и обменивается на сессию только после нажатия. После успешного подключения повторно использовать ссылку нельзя. Срок действия определяется настройкой Email OTP в Supabase; если он закончился, выпустить новую ссылку. Если браузер удалит своё хранилище, устройство потребуется подключить заново.

## Перенос истории

Перед обновлением на iPhone открыть прежнее приложение → «Копия в файл» и сохранить JSON.

- На прежнем домене данные читаются из того же ключа `gym-log-v1`. При первой записи создаётся дополнительная локальная копия `gym-log-v1-before-v2`.
- На новом домене браузер не передаст localStorage автоматически: нажать «Из файла» и выбрать сохранённый JSON.
- Для прежнего GitHub Gist есть «Перенос со старой версии» → «Загрузить прежнюю копию GitHub». Токен GitHub используется только для чтения Gist и не отправляется в Supabase. Новая версия больше не записывает изменения в Gist.
- Если в облаке и устройстве уже есть разные истории, выбрать копию явно. Перед выбором доступны скачивание обеих копий и локальная отмена. Автоматического слияния подходов пока нет.
- Полная старая структура сохраняется в `workout_state`, включая заметки, настройки упражнений, текущую форму и исторические агрегаты. Старые записи без отдельных подходов не превращаются в выдуманные подходы.
- Публичная сборка больше не включает встроенную личную историю от 28.09.2026. При переносе она дополнительно сохранена локально в `.local/legacy-seed-2026-09-28.json`; актуальнее будет JSON с iPhone или Gist.

Облако хранит последние 20 предыдущих версий тренировочного состояния. Это помогает при ошибочных изменениях, но не заменяет отдельную резервную копию. «Копия в файл» выгружает тренировки; питание и журналы интеграций находятся отдельно в Supabase и в эту копию не входят.

## Публикация по прежнему адресу

Workflow `.github/workflows/pages.yml` публикует сборку при push в `main` и может запускаться вручную. Для повторения настройки в другом репозитории:

1. Добавить в GitHub repository variables `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
2. В Settings → Pages выбрать **GitHub Actions** вместо публикации исходников ветки.
3. Сохранить изменения в `main` или вручную запустить **Publish WEDX**.

Workflow собирает `dist/` с базовым путём `/WEDX/`. Не публиковать исходный `index.html` как прежний одиночный файл: теперь ему нужна сборка. Для другого домена изменить `VITE_BASE_PATH` и Auth Redirect URLs.

В собранном приложении после первого успешного открытия кешируются интерфейс и скрипты. Оно может снова открываться без сети. Service Worker не кеширует ответы Supabase и не перезагружает страницу во время тренировки. Новая версия активируется после закрытия старых вкладок приложения. Первый запуск и подключение устройства требуют сети.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Либо `npm run check`. На macOS браузерные тесты используют установленный Chrome; на Linux/CI сначала `npx playwright install --with-deps chromium`.

SQL проверяется настоящим PostgreSQL-движком PGlite со стендом `auth.uid()` и ролями Supabase. Браузерные тесты проверяют миграцию, ввод подходов, офлайн, одноразовую ссылку, восстановление и обновление сессии, изоляцию аккаунтов, публичный визит без доступа к владельцу и истёкшую ссылку со смоделированными ответами Auth/API. Дополнительно на реальном проекте проверены вход владельца, перенос и точное чтение 134 записей. На временном аккаунте проверены изоляция данных, сохранение, конфликт ревизии, запрет анонимного чтения, импорт через опубликованную Edge Function, повтор запроса и отзыв токена. Временный аккаунт и его данные удалены после проверки. Команда Apple Health и разрешения на самом iPhone ещё не настроены.
