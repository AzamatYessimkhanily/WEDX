# Сон Apple Watch в WEDX

Раздел **«Сон»** хранит исходные отрезки и измерения отдельно от тренировок и питания. Дата эпизода — календарный день окончания сна, с часовым смещением из импорта. Дневной сон тоже сохраняется. История не обрезается при следующей загрузке.

## Для Apple Watch SE 2

- Стадии: базовый, глубокий, REM, бодрствование, сон без уточнённой стадии; «В постели», если такая запись есть.
- Начало/окончание каждого отрезка, длительность, записанные пробуждения и промежутки без данных.
- Отдельные измерения пульса, HRV **SDNN** и частоты дыхания с точным временем и единицей.
- Источник каждой записи. В экспорте также сохраняются версия источника, описание устройства, время создания и метаданные.

SE 2 не измеряет кислород и температуру запястья и не поддерживает уведомления об апноэ. В хранилище предусмотрены эти записи от поддерживаемых устройств, но они не выдумываются для SE 2. Оценка сна Apple, её компоненты, расписание и будильники текущим импортом не передаются. Сырые сигналы датчиков и ЭЭГ Apple Watch не экспортируются этим способом.

## Ежедневный импорт

1. В WEDX открыть **Сон → Подключить сон с Apple Watch → Создать ключ для сна**, скопировать ключ.
2. Скачать **«WEDX — Сон»**, открыть файл в «Командах» и вставить ключ при добавлении. Команду **«WEDX — Здоровье»** для питания менять не требуется.
3. Первый раз запустить на разблокированном iPhone, разрешить чтение четырёх показателей и отправку в свой WEDX.
4. После синхронизации часов повторить запуск и сравнить стадии и показатели с «Здоровьем». Автоматизация: **Команды → Автоматизация → Сон → Пробуждение → WEDX — Сон**. Доступность запуска без подтверждения зависит от настроек iOS; если данные часов пришли позже, повторить импорт.

Команда версии 3 читает последние **3 дня** без группировки по дням и без лимита количества записей. Сначала передаются стадии, затем HRV, дыхание и пульс отдельными запросами. Перед обработкой каждого показателя видно количество найденных записей; после отправки — результат. Пульс идёт последним, поскольку его записей может быть много. Ответ сервера, отличный от `status: imported`, останавливает дальнейшие этапы с уведомлением об ошибке. Сервер оставляет только измерения, пересекающиеся со сном; для сна с известным источником он также требует совпадения источников. Если последующее действие iPhone завершилось ошибкой, уже принятые стадии остаются. Повтор безопасен.

Версия 2 останавливалась после первого успешного запроса: на реальном iPhone блок сравнения значения словаря импортировался без правого операнда. Версия 3 сначала ищет точное текстовое совпадение `imported`, затем проверяет «имеет любое значение» (код 100, без поля сравнения). Эта проверка применяется ко всем четырём ответам; ошибки по-прежнему останавливают дальнейшие запросы. Реальный импорт стадий сна подтверждён 29 октября; прохождение остальных показателей требует отдельной проверки на iPhone.

На реальном iPhone обнаружены записи с пустым `Source`. Они сохраняются с исходным пустым `source_name` и `metadata.wedx_source_missing: true`, отдельно от известных источников. Интерфейс подписывает их «Источник не передан»; известные источники предпочтительнее по умолчанию. Если источник сна неизвестен, сервер сохраняет пересекающиеся по времени измерения с их собственными источниками. Это совпадение времени, а не подтверждение одного устройства: средние не вычисляются, отдельные значения и источники видны в «Измерения за это время» и JSON. Дневные измерения без пересечения со сном по-прежнему исключаются. При известном источнике сна действует прежнее требование совпадения источников. При совпадении времени разные значения без источника сохраняются отдельно, поскольку невозможно доказать, что это исправление одной записи. Полный XML-экспорт с `sourceName` позволяет получить данные с привязкой к устройству. Он не удаляет ранее сохранённые записи без источника; эти наборы не складываются.

На этапе 4/4 команда подготавливает отдельные записи пульса; тысячи записей требуют длительного прохода на iPhone. Уведомление «Найдено записей» означает начало подготовки, а не завершение импорта. Сервер возвращает `received`, `records`, `excluded` и указывает в сообщении число измерений, не связанных с загруженным сном. Запросы с `records: 0` не подтверждают сохранение измерений.

Сервер журналирует только категорию отказа и статическую причину проверки. Содержимое запросов, показатели, ключи и тексты исключений JSON.parse в журнал не попадают. Подписание файла и автоматические тесты не заменяют запуск Health-действий на iPhone.

В Source-фильтре нет переменной, из-за которой ранее падал импорт активных калорий. Источник извлекается из каждой записи; разные устройства не суммируются. В интерфейсе можно выбрать источник. По умолчанию приоритет получает последний источник с `Watch`/`часы` в названии, иначе последний доступный источник. Это правило WEDX, а не воспроизведение закрытого алгоритма приоритетов Apple Health.

## Полный экспорт и дополнительные данные

**Здоровье → фото профиля → Экспортировать все данные здоровья → Сохранить в Файлы**. В WEDX: **Сон → Подключить сон → Загрузить всю историю и дополнительные показатели**, выбрать ZIP или распакованный `apple_health_export/export.xml`.

Файл читается на устройстве потоком, другие категории не отправляются. Сначала импортируются отрезки сна, затем только пересекающиеся с ними измерения того же источника. Дополнительно принимаются `AppleSleepingWristTemperature`, `AppleSleepingBreathingDisturbances`, `SleepApneaEvent` и `SleepDurationGoal`, если они присутствуют в XML. Цель — запись из экспорта, а не придуманная цель WEDX. Уведомления Apple сохраняются как события, WEDX сам не выявляет апноэ.

Сохраняется абсолютная температура запястья, не отклонение от базовой температуры. Показатель нарушений дыхания хранится в единицах Apple `count`; он не переводится самовольно в диагноз или число пробуждений. Кислород из дроби HealthKit 0…1 приводится к процентам; исходные значение и единица остаются в записи.

Поддерживаются обычные ZIP с deflate/stored и XML до 2 ГБ. ZIP64, шифрованные и многотомные архивы нужно сначала распаковать в «Файлах». На браузерах без `DecompressionStream('deflate-raw')` тоже нужен XML. CRC и размер проверяются. При остановке/ошибке уже принятые пакеты сохраняются, импорт можно повторить. Неправильные единицы и даты не превращаются в нули.

## Данные и расчёт

`sleep_samples`: владелец, ключ записи, показатель, UTC start/end, исходное локальное время с UTC-смещением, источник/версия/устройство, стадия или числовое значение с нормализованной единицей, raw value/unit, JSON metadata, imported_at. Вкладка читает выбранный месяц страницами по 500 строк с запасом на переход месяца. На сервере сохраняется вся история.

Ключ — SHA-256 от показателя, источника, UTC-интервала и слоя (`in_bed` отдельно от стадий). Повтор не размножает записи, исправленное значение в том же интервале заменяет прежнее. Непустые метаданные из XML не затираются более простым импортом команды. Удаления в Health и сдвинутые интервалы автоматически не удаляют прежние строки WEDX: для полноценного зеркала нужен будущий нативный HealthKit anchored-query канал.

Эпизоды разделяются при перерыве более 90 минут. Это правило группировки WEDX, не физиологическая оценка. «В постели» и общий «Сон» не прибавляются поверх стадий. Противоречащие стадии становятся неизвестным интервалом; пробелы не засчитываются как сон. Начало/окончание — границы записанного сна, а не точное физиологическое время засыпания. Время до первого сна и доля сна в постели считаются только при наличии покрывающей записи «В постели» того же источника. Средние ночные показатели — арифметические средние отдельных измерений, не непрерывное наблюдение. В подробностях доступны все отдельные измерения и JSON-выгрузка.

`sleep-import` принимает `{version:1, source:'apple-health', samples:[{metric,start,end,source,value,unit,sourceVersion?,device?,metadata?}]}`. До 20 000 строк / 8 МБ. Авторизация: существующий отзывной `wedx_` ключ импорта Health либо сессия WEDX, проверенная Supabase Auth. Владелец никогда не берётся из тела запроса. RPC `ingest_sleep` доступен только `service_role`; RLS разрешает клиенту только SELECT своих строк. Запись питания и тренировок не вызывается. История не передаётся через существующий MCP тренера; отдельный инструмент сна можно добавить позже.

## Проверки и реальные ограничения

Проверяются RLS, запрет прямой записи, отзыв ключа, повтор/коррекция, сохранение метаданных, даты/единицы, DST, несколько источников, пересечения, дневной сон, пробелы, XML/ZIP, мобильный экран и смена аккаунта. Подписанный файл создаётся `scripts/build-sleep-shortcut.py` и `shortcuts sign`. Подпись и тест структуры не подтверждают работу Health-действий на конкретном iPhone. Первый реальный запуск и сверка данных требуют iPhone пользователя и его разрешений Health; до этого не следует писать, что личный сон уже загружен.
