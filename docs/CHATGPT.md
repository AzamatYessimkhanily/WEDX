# WEDX в ChatGPT

Личный MCP-плагин читает облачные данные WEDX: программу и историю тренировок, подходы, заметки, замеры веса, питание Apple Health и нормы WEDX. Изменять записи через него нельзя. Каждый вызов получает свежий снимок из базы; несинхронизированные записи телефона появятся после синхронизации WEDX.

## Подключение

1. В веб-версии ChatGPT открыть **Плагины → Добавить → Добавить пользовательский MCP-сервер**.
2. Название **WEDX**, URL скопировать из **WEDX → Питание → ChatGPT — тренер → Скопировать адрес MCP**. Авторизация **OAuth**; сервер поддерживает автоматическую регистрацию через CIMD, отдельный client secret не нужен.
3. Создать личный плагин и начать установку/подключение. В открывшемся окне WEDX потребуется одноразовый код.
4. В WEDX на своём подключённом iPhone нажать **Создать код подключения**, скопировать код в окно подтверждения и нажать **Разрешить чтение**. Код действует 10 минут и используется один раз. Не отправлять его в чат.
5. В ChatGPT на iPhone, в том же аккаунте, выбрать **@WEDX** в новом чате. Пример: «Разбери мой прогресс за 14 дней: вес, питание, белок и тренировки. Цель — снижать жир и сохранять мышцы».

Отключение: **WEDX → Питание → ChatGPT → Отключить ChatGPT**. Оно отзывает токены выбранного подключения, но не удаляет уже отправленные в ChatGPT ответы.

## Контракт

Endpoint: `${SUPABASE_URL}/functions/v1/wedx-coach/mcp`, Streamable HTTP, stateless JSON responses. Шесть инструментов: `get_fitness_profile`, `get_fitness_overview`, `get_training_program`, `get_workouts`, `get_nutrition`, `get_weight_history`.

Инструменты возвращают время запроса и синхронизации, пропущенные дни, неизвестные значения и действовавшие на дату цели. Наличие дневной записи не подтверждает полноту дневника. Норма питания — не базовый обмен; остаток до нормы — не измеренный энергетический дефицит. Потерю мышц и причины изменения веса эти данные не доказывают. Сон, состав тела и посещения Invictus не подключены.

## Авторизация и развёртывание

- Миграции `20261023160000_coach_mcp.sql` и `20261023161000_coach_read_permissions.sql`; Edge Function `wedx-coach` с `verify_jwt=false`, поскольку она самостоятельно проверяет отдельные opaque OAuth-токены. Все запросы данных ограничены владельцем проверенного токена. Сервису дан только SELECT к трём исходным таблицам, права прямой записи не добавляются.
- OAuth 2.1: PKCE S256, одноразовый authorization code, привязка client/redirect/resource, scope `wedx:read`, access token на час, ротация refresh token до 90 дней. Повтор старого refresh token отзывает grant. До 120 обращений к MCP в минуту на grant.
- Поддерживается CIMD только `https://chatgpt.com/oauth/client.json` и документ конкретного callback на том же домене. Проверяются документ клиента, адрес возврата и `iss` в callback. Произвольные адреса регистрации не загружаются.
- Хеши токенов и кодов хранятся в таблицах `coach_*`, недоступных `anon`/`authenticated`. Для управления своим подключением `/manage` проверяет действующую сессию WEDX через Supabase Auth. OAuth-токены не дают доступ к API записи приложения.
- Подпуть issuer обнаруживается через OIDC fallback `/.well-known/openid-configuration`. Для совместимости реализован настоящий OIDC `openid`, RS256 ID token, `/jwks` и `/userinfo` (только `sub`). В Supabase Vault необходим секрет `wedx_coach_oidc` с `{privateJwk,publicJwk}`. Приватная часть никогда не отправляется клиенту; публичный JWK содержит `kty,n,e,kid,use,alg`. Ключ RSA 2048 создаётся административно, вне репозитория. После замены секрета перезапустить функцию; при смене ключа нужно учитывать ещё действующие ID tokens.
- В deploy входят все файлы `supabase/functions/wedx-coach`, а также используемые `src/domain/program.js` и `src/features/integrations/metrics.js` с сохранением относительных путей.
- `coach.html` — отдельная точка входа Vite: она не загружает редактор, сессию или локальную историю. Одноразовый код не сохраняется в localStorage и не попадает в URL.
- Цель и часовой пояс — `coach_preferences` владельца; отсутствие цели явно возвращается как `null`.

Проверки: `npm run check`, официальный MCP SDK (discovery/initialize/list/call), тесты PKCE/владельца/отзыва/ротации и браузерные сценарии подключения. Production-проверка проводится временным grant, который затем отзывается.

Официальная настройка: [Custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server), [OAuth](https://developers.openai.com/plugins/build/auth), [плагины на телефоне](https://learn.chatgpt.com/docs/plugins).
