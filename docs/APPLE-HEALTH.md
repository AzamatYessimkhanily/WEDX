# Приём питания из YAZIO через Apple Health

Серверная часть импорта подготовлена. Для настоящей передачи нужны проект Supabase, развёрнутая функция и команда на iPhone. Само наличие endpoint не подключает YAZIO.

## Развёртывание

После применения миграции:

```sh
supabase link --project-ref <project-ref>
supabase functions deploy health-import
```

В `supabase/config.toml` у функции `verify_jwt = false`: стандартный JWT-шлюз отключён, потому что функция **сама проверяет отдельный интеграционный токен**. Анонимные запросы без правильного токена отклоняются. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляются средой Supabase; не переносить service-role key в приложение или команду iPhone.

В WEDX войти → «Подключения и питание» → «Создать ключ для команды». Сохранить показанные адрес и токен. В базе хранится только хеш токена. «Отозвать» прекращает приём по этому ключу.

## Контракт запроса

`POST https://<project-ref>.supabase.co/functions/v1/health-import`

Заголовки: `Content-Type: application/json`, `Authorization: Bearer wedx_<token>`.

```json
{
  "version": 1,
  "source": "yazio:apple-health",
  "requestId": "33333333-3333-4333-8333-333333333333",
  "days": [
    { "date": "2026-10-21", "caloriesKcal": 2250, "proteinGrams": 155.5 }
  ]
}
```

Здесь числа — пример формата, не целевые значения питания. На каждый день отправляется **полный итог**, а не добавка. Повторный импорт обновляет день; он не суммируется с прежним итогом. При исправлении дневника отправить новый `requestId`. Повтор той же попытки должен использовать прежний `requestId` и те же значения. Удалённые записи питания можно исправить новым итогом, в том числе нулём.

Ответ: `{"status":"imported","records":1}` либо `duplicate`. Ошибки: 400 — формат, 401 — ключ, 409 — тот же requestId с другим содержимым, 413 — размер, 429 — частота, 503 — временная недоступность. Не считать неуспешный запрос синхронизированным.

## Настройка команды на iPhone

1. Включить передачу питания YAZIO в Apple «Здоровье». Убедиться, что там есть калории питания и белок с источником YAZIO.
2. В «Командах» получить записи **пищевой энергии** за выбранный календарный день, отфильтровать источник YAZIO и суммировать в **ккал**. Не брать «Энергию активности» или «Энергию покоя».
3. Аналогично получить белок за тот же интервал, только из YAZIO, и суммировать в **граммах**. Не складывать эти показатели с копиями из других приложений.
4. Сформировать дату `yyyy-MM-dd` в часовом поясе телефона, новый UUID и JSON выше. Для повторной попытки сохранить UUID и тело.
5. Действием «Получить содержимое URL» отправить POST с заголовками и JSON. Проверить результат и появление дня в WEDX.
6. Сначала проверить запуск вручную и сверить итог с YAZIO. Затем можно добавить личную автоматизацию. Доступ к данным здоровья при блокировке и фоновый запуск зависят от iOS; если запрос не прошёл, повторить после разблокировки.

Веб-страница сама не читает HealthKit. Готового подписанного файла `.shortcut` в репозитории пока нет; точные названия параметров нужно проверить в «Командах» на iPhone пользователя.

Официальные источники: [обмен данными YAZIO](https://help.yazio.com/hc/en-us/articles/203444951-Terms-of-Use-Privacy-Policy), [чтение показателей в «Командах»](https://support.apple.com/guide/shortcuts/intro-to-find-and-filter-actions-apd3c845e881/ios), [HTTP-запросы в «Командах»](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios).
