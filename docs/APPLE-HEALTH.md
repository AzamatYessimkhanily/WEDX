# YAZIO → Apple «Здоровье» → WEDX

Команда «WEDX — питание 4» передаёт:

- пищевую энергию, белок, углеводы и общий жир **только из YAZIO** за сегодня и предыдущие 7 календарных дней;
- записи активной энергии за сегодня и вчера с источниками и временем, чтобы обнаружить конкурирующие/пересекающиеся записи. Более ранняя история активности сохраняется; исправления старше двух дней этим режимом не загружаются. Ограниченное окно избегает повторного медленного перебора всей недели при каждом закрытии YAZIO.

В базе хранятся дневные итоги и время обновления каждого показателя, без продуктов и сырых записей Health. Команда ничего не записывает в «Здоровье». Веб-приложение само не читает HealthKit. Сон, вес и тренировки этим импортом не передаются.

## Подключение и обновление

1. В [WEDX → Apple Health](https://azamatyessimkhanily.github.io/WEDX/?view=health) подключить свой iPhone по личной ссылке, если это ещё не сделано.
2. Скопировать существующий ключ из первого действия «Текст» прежней команды. Новый ключ нужен только при отсутствии прежнего; его можно создать в WEDX.
3. Открыть [шаблон в iCloud](https://www.icloud.com/shortcuts/b99072bde9754f2ab41d9349ea936fbe), добавить «WEDX — питание 4» и вставить ключ при установке. Резервный подписанный файл: `public/shortcuts/WEDX — питание 4.shortcut`.
4. Запустить на разблокированном iPhone. Разрешить чтение пищевой энергии, белка, углеводов, общего жира и активной энергии, затем передачу в свой проект Supabase. При запросе больших объёмов: Настройки → Приложения → Команды → Дополнения → Передача крупных объёмов данных.
5. В существующей автоматизации «Когда YAZIO закрывается» выбрать новую команду вместо «WEDX — питание 2». Режим — немедленный запуск. Старые версии продолжают передавать калории и белок; они не стирают дополнительные показатели.
6. Вернуться в WEDX и раскрыть день. Сверить значения с «Здоровьем» и YAZIO. Различия в экспорте или округлении не исправляются выдуманными числами.

Автоматизация создаётся на iPhone, не синхронизируется с Mac. Если YAZIO ещё не успел обновить «Здоровье» или телефон заблокирован, повторить запуск вручную. При открытии WEDX, возврате на экран, восстановлении интернета и каждые 15 секунд на переднем плане приложение получает свежие итоги. При сбое показывает последние загруженные данные с предупреждением; запросы и таймеры прекращаются при уходе со страницы.

## Достоверность и цели

Пустой список не равен нулю: он может означать отсутствие доступа или записей. День без энергии или белка пропускается. Отсутствующие жиры/углеводы не стирают старые значения; время каждого показателя позволяет увидеть, когда именно он был получен. Полностью удалённый дневник автоматически не обнуляет прошлый импорт. Наличие записей не доказывает, что дневник заполнен полностью.

«Расход активности YAZIO» принимается, только если **все** полученные записи активной энергии дня относятся к одному источнику YAZIO, имеют корректное время и не пересекаются. При наличии другого трекера, пересечений или интервала через полночь расход неизвестен и не участвует в лимите. Сырые суммы нескольких источников не воспроизводят приоритеты Apple Health. Это намеренно консервативная проверка, не замена статистическому запросу HealthKit. Расход активности не является полным расходом организма за сутки. Доступ к Health может скрыть отдельные записи, поэтому нужна первоначальная сверка на телефоне.

YAZIO не экспортирует свои дневные цели через этот канал. `nutrition_goals` хранит **ручные настройки WEDX** с `effective_from`, базовым лимитом, фиксированной целью белка и флагом прибавления активности. Новая цель не распространяется на более ранние дни. При изменении целей в YAZIO их нужно обновить в WEDX. Автоматическое изменение макроцелей YAZIO не воспроизводится.

`src/features/integrations/metrics.js` предоставляет для будущей аналитики единый дневной объект:

| Поле | Источник |
| --- | --- |
| `date` | Календарная дата iPhone |
| `calories_consumed`, `protein_g`, `carbs_g`, `fat_g` | Итоги записей YAZIO в Health |
| `calories_burned` | Только однозначные записи активной энергии YAZIO; иначе null |
| `base_calorie_goal`, `protein_goal_g` | Ручная цель, действующая на дату |
| `adjusted_calorie_goal` | База + подтверждённая активность, если включено; иначе база |
| `calories_remaining` | Лимит − съедено; отрицательное значение = превышение |
| `protein_remaining_g` | Цель белка − полученный белок |
| `calorie_balance` | Съедено − лимит, **не физиологический дефицит/профицит** |
| `last_synced_at` | Последний принятый импорт дня |
| `metric_synced_at`, `activity_status`, `goal_source`, `goal_effective_from` | Происхождение и свежесть данных |

Расчётные поля не дублируются в базе: это исключает рассогласование с исходными значениями. Если исходный показатель неизвестен, зависимый расчёт тоже null. Графики и выводы о весе/мышцах пока не добавлены.

## Серверный контракт

`POST https://<project-ref>.supabase.co/functions/v1/health-import`, заголовки `Content-Type: application/json`, `Authorization: Bearer wedx_<token>`.

```json
{
  "version": 3,
  "source": "yazio:apple-health",
  "startDate": "2026-10-15",
  "endDate": "2026-10-22",
  "activityStartDate": "2026-10-21",
  "energySamples": [{"date":"2026-10-22","source":"YAZIO","value":500.25,"unit":"kcal"}],
  "proteinSamples": [{"date":"2026-10-22","source":"YAZIO","value":30.5,"unit":"g"}],
  "carbsSamples": [{"date":"2026-10-22","source":"YAZIO","value":45.25,"unit":"g"}],
  "fatSamples": [{"date":"2026-10-22","source":"YAZIO","value":18.75,"unit":"g"}],
  "activitySamples": [{"date":"2026-10-22","source":"YAZIO","value":159.5,"unit":"kcal","start":"2026-10-22T12:00:00.000+05:00","end":"2026-10-22T12:10:00.000+05:00"}]
}
```

Числа — примеры, не рекомендации питания. Даты локальные, время активности содержит UTC-смещение. Пределы: 1 МБ, 31 день, 4000 записей на пищевой показатель (16000 вместе), 6000 активности. Единицы нормализуются в ккал и граммы, точность до 0.001. Неизвестные единицы/некорректные значения отклоняют весь запрос. Одинаковые пищевые записи не удаляются — это могут быть разные блюда.

`activityStartDate` необязателен для старых V3-команд и по умолчанию равен `startDate`; дни до этой границы не обновляют активность и её время синхронизации.

V1 (дневные итоги, UUID, 64 КБ) и V2 (энергия/белок) совместимы. Каждый V2/V3 запуск получает новый UUID, а дневные итоги **заменяются**, не прибавляются. Пустые/невалидные запросы диагностируются отдельно. Ключ хранится в базе только в SHA-256; RPC доступен серверной service_role и разрешает только импорт этих итогов. RLS изолирует цели и питание владельцев. Сервисный ключ никогда не передаётся в браузер или команду.

## Генератор и проверки

```sh
python3 scripts/build-health-shortcut.py --output .local/health-v3.wflow
shortcuts sign -m anyone -i .local/health-v3.wflow -o 'public/shortcuts/WEDX — питание 4.shortcut'
npm run check
```

Публичный шаблон содержит только заполнитель ключа. Персональный вариант `--token-file` разрешён только в игнорируемой `.local/`. После изменения шаблона нужно создать новую ссылку iCloud и обновить панель/тесты. `--mock` подставляет синтетические записи и не обращается к Health или серверу.

22.10.2026 проверены импорт нового подписанного шаблона и вопрос о ключе на Mac. Mock выполнен в редакторе «Команд»: точные значения 200.25/799.75 ккал, 45.5 г белка, 100.25 г углеводов, 35.75 г жира, 159.5 ккал активности и время `+05:00`; чужой пищевой источник исключён. Это не заменяет проверку реальных Health-действий на iPhone.

Критичные параметры экспорта: числа словаря имеют `WFItemType: 3`; HTTP File body требует **прямой** `WFTextTokenAttachment` в `WFRequestVariable`, не текстовую обёртку. Обёртка отправляет пустое тело на iPhone.
