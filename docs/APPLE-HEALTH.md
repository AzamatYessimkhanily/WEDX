# Семь показателей Apple Health в WEDX

Актуальная команда — **«WEDX — Здоровье»**. [Скачать актуальную команду](https://azamatyessimkhanily.github.io/WEDX/shortcuts/WEDX%20%E2%80%94%20%D0%97%D0%B4%D0%BE%D1%80%D0%BE%D0%B2%D1%8C%D0%B5.shortcut?v=7). Подписанный резервный файл: `public/shortcuts/WEDX — Здоровье.shortcut`.

| Показатель | Источник |
| --- | --- |
| Съедено, ккал | Пищевая энергия Apple Health |
| Белок, г | Белки Apple Health |
| Углеводы, г | Углеводы Apple Health |
| Жиры, г | Общий жир Apple Health |
| Сожжено активностью, ккал | Активная энергия одного Apple Watch |
| Дневная норма без активности, ккал | Ручная датированная настройка WEDX, например из YAZIO |
| Осталось калорий | Норма + активность − съедено; при отключённом учёте активности — норма − съедено |

Дневная норма **не равна базовому обмену**. «Осталось» не является оценкой физиологического дефицита. YAZIO не экспортирует свою дневную норму через этот канал; при её изменении нужно обновить настройку WEDX.

В «Питании» все загруженные дни доступны в календаре по месяцам. История читается страницами без отсечения до восьми последних записей; при смене месяца октябрь остаётся доступен. Зелёная галочка — калории в пределах скорректированной нормы и белок набран; красный плюс — превышение калорий; жёлтая «Б» — белок ниже выбранной цели. Перебор и недобор белка могут отмечаться одновременно. Сегодняшний день остаётся незавершённым: перебор виден сразу, недобор белка до конца дня не считается итогом. Пустые даты не получают оценку.

Цель белка = последний замер веса **на дату дня или раньше** × коэффициент, округлённая до грамма. Начальный ориентир 2 г/кг можно изменить в «Настройки → Настроить норму» с выбранной даты. Более поздние замеры не используются для прошлых дней; без подходящего замера оценка белка не выставляется. Прежние фиксированные цели YAZIO сохраняются в базе для совместимости, но экран использует расчёт по весу. Этот ориентир и цвет календаря не измеряют потерю мышц. Основание для выбора: [позиция ISSN по белку и тренировкам](https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/).

## Настройка на iPhone

1. В прежней рабочей команде WEDX нажать «…» и скопировать ключ из первого действия «Текст» (начинается с `wedx_`). Не отправлять ключ в чат. При отсутствии ключа создать его в WEDX → Питание → Настройки.
2. Скачать актуальный файл в Safari и открыть его из загрузок. Добавить «WEDX — Здоровье», выбрать «Заменить» и вставить сохранённый ключ при установке.
3. Запустить на разблокированном iPhone. Разрешить чтение пищевой энергии, белка, углеводов, общего жира и активной энергии, затем передачу итогов в свой WEDX.
4. Дождаться уведомления «Дней обновлено». Открыть WEDX → Питание и сверить сегодняшний день с пятью соответствующими показателями «Здоровья». При ошибке сохранить точный текст уведомления. Не переключать автоматизацию до успешной проверки.
5. «Команды» → «Автоматизация» → «Когда закрывается YAZIO» → действие запуска команды: **«WEDX — Здоровье»**; режим **«Запускать немедленно»**.
6. После проверки удалить прежние «WEDX — питание», «питание 2», «питание 3», «питание 4» и тестовые WEDX-команды. Оставить одну рабочую команду и одну автоматизацию. Чужие команды не удалять.

В WEDX уже сохранённая дневная норма применяется с её даты. Новая настройка не меняет прошлые дни. WEDX получает обновления при открытии и каждые 15 секунд на переднем плане. Автоматизация iPhone не означает непрерывную фоновую синхронизацию: если YAZIO ещё не записал изменения в Health или iOS не дал выполнить команду, повторить запуск на разблокированном телефоне.

### Ошибка в запросе активности с фильтром «Источник»

На проверенном iPhone автоматическая переменная «Результат выполнения условия» в поле «Источник» вызывает общую ошибку действия. Ограничение первого поиска до 100 записей не исправляет этот отдельный сбой. В **последнем** «Найти данные здоровья», где тип `Active Calories` и группировка «День», нажать переменную в строке «Источник» → «Очистить», затем выбрать свои Apple Watch из списка источников. Сам фильтр источника должен остаться, дневной запрос должен оставаться без ограничения результатов. Выбор сохраняется в установленной команде.

28.10.2026 пользователь выполнил эту замену и подтвердил успешный запуск. Сервер принял запрос в 10:20 UTC; импорт за 27.10 заменил 775 на **549 ккал**, статус `verified`. Это подтверждённый способ для текущего iPhone. Автоматическая подстановка источника в публичном шаблоне `?v=6` остаётся ограничением: переустановка этого файла потребует повторно выбрать часы вручную. Не заменять уже работающую команду ради обновления файла без необходимости.

## Импорт всего месяца

Ревизия файла `?v=7` обновляет 31 календарный день за один запуск. Это охватывает весь текущий месяц; ранее импортированные даты остаются в базе и календаре. Формат запроса V5 и ограничение сервера до 31 дня уже поддерживают этот период. Даты без пищевой энергии или белка не подставляются и не заполняются нулями.

Для работающей команды на iPhone переустановка не нужна: в начале заменить «Вычесть 7 дней» на «Вычесть 30 дней», а во всех шести «Найти данные здоровья» заменить «в последних 8 дней» на «в последних 31 день». Сохранить выбранные вручную Apple Watch, группировку «День» в пяти итоговых запросах и ограничение 100 только в первом поиске источника. Запустить и сверить начало октября. Публичный шаблон сохраняет описанное выше ограничение динамического источника: при новой установке часы нужно выбрать вручную.

## Передача дневных итогов

Пять Find Health Samples используют `WFHKSampleFilteringGroupBy: Day`, `WFHKSampleFilteringFillMissing: false`, без лимита результатов. Запрашиваются последние 31 сутки, принимаются 31 календарный день от сегодня минус 30 дней до сегодня. Дополнительный крайний день не импортируется, чтобы не перезаписать старейший день частичной суммой.

Для активности сначала запрашиваются **не более 100 последних образцов** за 31 сутки от новых к старым. Одно нативное действие извлекает их названия источников; регулярное выражение находит название с `Watch` или `часы`, выбирается первый (последний использованный) источник. Затем **отдельный** запрос ограничивается точным названием этого источника **до** группировки по дням и читает все записи периода без лимита. Нет поэлементного цикла по интервалам, нет добавления активности iPhone, YAZIO или других трекеров. Питание по-прежнему передаётся дневными итогами всех источников.

Ревизия файла `?v=6` ограничивает только поиск названия часов; формат запроса остаётся V5. Это устраняет неограниченную загрузку сырых записей в новом блоке, на котором пользователь сообщил о сбое. Подтверждение причины и успешного запуска требует проверки на iPhone. Для уже установленной V5 ту же правку можно сделать в **первом** «Найти данные здоровья»: включить «Ограничение» и установить 100. Пять последующих запросов с группировкой по дням должны оставаться без лимита.

Группировка «По дням» сама по себе не гарантирует устранения дублей между источниками. Именно этот дефект был в V4: за 27 октября команда передала 775 ккал вместо заявленных пользователем 549 ккал «Подвижности». Сервер и экран не прибавляли разницу; в базе сохранялась уже завышенная сумма. V4 продолжает обновлять еду, но больше не меняет активность; уведомление просит обновить команду. Ранее сохранённые `health_total` не используются ни для расхода, ни для остатка. Исходные данные остаются в базе до корректного повторного импорта.

Если источник часов не найден среди 100 последних образцов, запрос активности не выполняется; нет возврата к сумме всех источников. При нескольких часах берётся один последний источник, поэтому при смене часов старые дни могут отсутствовать. Переименованные часы без `Watch`/`часы` также не определяются автоматически. Это фильтрация источника, а не прямой запрос кольца Fitness (`HKActivitySummary` недоступен в этих действиях Shortcuts). Реальное совпадение с «Подвижностью» нужно проверить на iPhone; Mac выполняет только тестовый вариант без Health.

Отсутствие записей не заполняется нулями. День без калорий или белка пропускается, прежние данные сохраняются. Отсутствующие жиры/углеводы не стирают прошлые значения; время каждого показателя видно на экране. Отсутствующий расход явно становится неизвестным, зависимый остаток тоже неизвестен. Явный ноль допускается. Полностью удалённый дневник автоматически не обнуляет старый импорт.

## Контракт V5

`POST https://<project-ref>.supabase.co/functions/v1/health-import`, заголовки `Content-Type: application/json`, `Authorization: Bearer wedx_<token>`.

```json
{
  "version": 5,
  "source": "apple-health",
  "aggregation": "day",
  "activitySelection": {"mode":"single-source","source":"Apple Watch (Test)"},
  "startDate": "2026-10-16",
  "endDate": "2026-10-23",
  "energyTotals": [{"date":"2026-10-23","value":1321,"unit":"kcal"}],
  "proteinTotals": [{"date":"2026-10-23","value":58,"unit":"g"}],
  "carbsTotals": [{"date":"2026-10-23","value":121,"unit":"g"}],
  "fatTotals": [{"date":"2026-10-23","value":70,"unit":"g"}],
  "activityTotals": [{"date":"2026-10-23","value":90,"unit":"kcal"}]
}
```

Числа иллюстрируют формат, не рекомендуют питание. Один итог на дату на показатель. Повторяющиеся даты отклоняются целиком, не суммируются. До 31 принятого дня и 32 входящих итогов на показатель (с дополнительным крайним днём). Проверяются диапазоны, календарные даты, единицы и конечность чисел; значения нормализуются в ккал/г с точностью 0.001. HealthKit `Cal` (большая калория) и Foundation `kCal` принимаются как ккал; `cal` с маленькой буквы остаётся 0.001 ккал. Регистр не меняется, чтобы не внести ошибку в 1000 раз. При невалидном поле уведомление указывает показатель, поле и единицу, не раскрывая запрос или ключ.

В БД сохранён исторический ключ `source = yazio:apple-health`, чтобы обновлять прежнюю строку дня без дублей. V5 задаёт `nutrition_origin = apple-health` и `activity_status = verified` для выбранного источника часов, `no_data` при отсутствии. `verified` означает проверенный формат одного источника, а не независимую проверку точности часов. Статус `health_total` оставлен в схеме для исторических V4-записей. V4 не передаёт поля активности в RPC, поэтому старая автоматизация не перезапишет исправленный расход.

Сохраняются только дневные итоги. Повторный импорт заменяет день, не прибавляет к нему; каждый запуск получает новый UUID. Токен хранится на сервере как SHA-256 и даёт только право импорта питания. RLS, ограничение частоты, защита владельцев и совместимость V1–V3 сохранены. Старые команды не стирают новые макросы, но могут вернуть питание к данным только YAZIO, поэтому после перехода их следует удалить.

## Генератор и проверка

```sh
python3 scripts/build-health-shortcut.py --output .local/health-daily.wflow
shortcuts sign -m anyone -i .local/health-daily.wflow -o 'public/shortcuts/WEDX — Здоровье.shortcut'
npm run check
```

Публичный шаблон содержит заполнитель ключа, не личный ключ. `--token-file` разрешён только для игнорируемой `.local/`. `--mock` заменяет Health синтетическими дневными итогами и ничего не отправляет.

Критичные параметры: числовые значения словаря — `WFItemType: 3`; HTTP File body — прямой `WFTextTokenAttachment` в `WFRequestVariable`. Встроенная группировка должна оставаться `Day`; при ошибке сервер отклонит повторяющиеся даты вместо сложения.

23.10.2026: подписанный шаблон успешно импортирован на Mac, проверен вопрос о ключе и опубликован с заполнителем. Автоматические тесты проверяют контракт, миграцию, повторы, исправления, пропуски, единицы, RLS и семь полей интерфейса. Реальное выполнение Health-запросов и совпадение цифр требуют запуска пользователем на iPhone.
