# YAZIO → Apple «Здоровье» → WEDX

Передаются пищевая энергия и белок из YAZIO за сегодня и предыдущие 7 календарных дней. Вес и тренировки уже ведутся в WEDX. Сон и другие показатели пока не передаются.

Веб-приложение само не читает HealthKit. Нужна бесплатная команда Apple на iPhone и разрешение пользователя на чтение двух показателей. Данные передаются в собственный проект WEDX в Supabase. Записи «Здоровья» не изменяются. В базе сохраняются только итоги по дням, без названий продуктов.

## Подключение на iPhone

1. В «Здоровье» → «Питание» проверить пищевую энергию и белок. В записях обоих показателей должен быть источник YAZIO.
2. В WEDX нажать «Apple Health» в верхней панели (кнопка доступна и в дни отдыха). Прямая ссылка: `https://azamatyessimkhanily.github.io/WEDX/?view=health`. Если устройство ещё не подключено к своей истории, открыть личную ссылку и нажать «Подключить это устройство». Затем нажать «Создать ключ для iPhone» → «Скопировать ключ».
3. Нажать «Установить команду». Если Safari скачал файл, открыть его из «Загрузок» Safari или приложения «Файлы». При добавлении команды вставить ключ `wedx_…`.
4. Запустить «WEDX — питание» на разблокированном iPhone. Разрешить чтение пищевой энергии и белка, затем отправку в домен своего проекта Supabase.
5. В WEDX нажать «Обновить питание». Сверить калории и белок одного завершённого дня с YAZIO. Повторить запуск: итог должен остаться тем же, не удвоиться.
6. Исправить запись в YAZIO, дождаться обновления «Здоровья» и повторить команду: итог в WEDX должен замениться.

Если WEDX открывается через иконку на главном экране, скопировать личную ссылку из чата, открыть WEDX через эту иконку и вставить ссылку в поле «Личная ссылка WEDX» в разделе «Подключение устройства». Нажать «Подключить это устройство». Это выполняет подключение в самом установленном приложении. Удалять приложение не требуется. Ещё не использованная ссылка переживает обновление вкладки в течение часа; после подключения или отказа сервера она удаляется из временного хранилища.

Присутствие записи не подтверждает полноту дневника. Сегодняшний день обычно ещё заполняется. Если за день нет одного из показателей, день пропускается, прежнее значение сохраняется. Отсутствие записей при запрете доступа неотличимо от пустого дневника; автоматически заменять такие дни нулями нельзя. Полное удаление всех записей дня также не обнуляет уже импортированный итог — это требует отдельной проверки.

Проверка на реальных данных и разрешения выполняются на iPhone. macOS не даёт доступ к HealthKit; подпись файла и серверные тесты не заменяют проверку двух Health-действий на телефоне. При различиях версий iOS в действиях «Найти образцы Здоровья» проверить типы «Пищевая энергия» (Dietary Calories) и «Белки» (Protein), отсутствие группировки и ограничения количества записей.

## Автоматизация после сверки

«Команды» → «Автоматизация» → «+» → «Приложение» → YAZIO → «Закрывается» → «Немедленный запуск» → «WEDX — питание».

Выход из YAZIO не гарантирует, что запись уже успела появиться в «Здоровье». Команда повторно читает предыдущие дни и исправляет их при следующих запусках. Если iPhone заблокирован, HealthKit может быть недоступен; повторить вручную после разблокировки. Первый запуск всегда выполнить вручную.

## Сборка команды

Генератор: `scripts/build-health-shortcut.py` (Python 3, без зависимостей).

```sh
python3 scripts/build-health-shortcut.py --output .local/health-template.unsigned.shortcut
shortcuts sign --mode anyone --input .local/health-template.unsigned.shortcut --output public/shortcuts/WEDX-Nutrition.shortcut
```

Публичный файл не содержит ключа и задаёт вопрос о ключе при добавлении. Apple получает копию команды при подписании. Личный вариант допускается только в игнорируемой `.local/`: передать `--token-file` с JSON `{"token":"wedx_…"}`. Не публиковать личный вариант.

`--mock` заменяет только чтение Health на синтетические записи и выводит JSON без HTTP-запроса. Такой вариант проверяет сборку списков, отбор источника и JSON в приложении «Команды», но не доступ к настоящим данным HealthKit.

## Приёмник

`POST https://<project-ref>.supabase.co/functions/v1/health-import`

Заголовки: `Content-Type: application/json`, `Authorization: Bearer wedx_<token>`.

Подписанная команда использует контракт v2:

```json
{
  "version": 2,
  "source": "yazio:apple-health",
  "startDate": "2026-10-14",
  "endDate": "2026-10-21",
  "energySamples": [
    { "date": "2026-10-21", "source": "YAZIO", "value": 500, "unit": "kcal" }
  ],
  "proteinSamples": [
    { "date": "2026-10-21", "source": "YAZIO", "value": 30, "unit": "g" }
  ]
}
```

Числа — пример формата, не цели питания. Даты формируются на iPhone в местном часовом поясе с форматом `yyyy-MM-dd`. Поиск охватывает запасной восьмой прошедший день, чтобы нижняя граница не обрезала первый календарный день; приёмник исключает всё вне startDate/endDate. Сначала команда отбирает источник YAZIO, затем сервер повторно проверяет источник, единицы, диапазоны и размеры.

Лимиты v2: 1 МБ; до 4000 записей на показатель, 6000 вместе; до 31 дня. Ккал/кДж/Дж/кал и г/мг/кг нормализуются сервером. Если неизвестны единицы или значение, весь запрос отклоняется. Одинаковые по величине записи не удаляются: это могут быть разные блюда. Повторные запуски заменяют дневной итог через существующий `ingest_nutrition`, не прибавляют к нему. Сервер создаёт новый UUID на каждый запуск, поэтому исправление и последующий возврат к прежним значениям также работают.

Старый контракт v1 с `requestId` UUID и `days: [{date, caloriesKcal, proteinGrams}]` сохраняется (64 КБ). Повтор той же попытки v1 должен иметь прежние UUID и содержимое, исправление — новый UUID. Нулевые итоги v1 допустимы только как явная корректировка.

Ответ содержит `status`, `records`, `message` и при успешной записи `skippedDays`. `no_data` не является успешным сохранением и не меняет базу. Команда показывает сообщение приёмника; сетевые ошибки обрабатывает само приложение «Команды».

## Развёртывание и ключи

```sh
supabase link --project-ref <project-ref>
supabase functions deploy health-import
```

У функции `verify_jwt = false`: она проверяет свой узкий интеграционный токен через RPC. В базе хранится только SHA-256 ключа. Ключ разрешает импорт питания, не чтение/изменение тренировок. «Отозвать» прекращает приём. `SUPABASE_SERVICE_ROLE_KEY` остаётся только в среде Supabase; он не нужен команде или веб-приложению.
