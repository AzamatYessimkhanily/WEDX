# Семь показателей Apple Health в WEDX

Актуальная команда — **«WEDX — Здоровье»**. [Установить через iCloud](https://www.icloud.com/shortcuts/6df804e55175488686de84f1b0d80a9f). Подписанный резервный файл: `public/shortcuts/WEDX — Здоровье.shortcut`.

| Показатель | Источник |
| --- | --- |
| Съедено, ккал | Пищевая энергия Apple Health |
| Белок, г | Белки Apple Health |
| Углеводы, г | Углеводы Apple Health |
| Жиры, г | Общий жир Apple Health |
| Сожжено активностью, ккал | Активная энергия Apple Health |
| Дневная норма без активности, ккал | Ручная датированная настройка WEDX, например из YAZIO |
| Осталось калорий | Норма + активность − съедено; при отключённом учёте активности — норма − съедено |

Дневная норма **не равна базовому обмену**. «Осталось» не является оценкой физиологического дефицита. YAZIO не экспортирует свою дневную норму через этот канал; при её изменении нужно обновить настройку WEDX. Цели белка, остаток белка и отдельный баланс не отображаются. Старые настройки не удаляются.

## Настройка на iPhone

1. В прежней рабочей команде WEDX нажать «…» и скопировать ключ из первого действия «Текст» (начинается с `wedx_`). Не отправлять ключ в чат. При отсутствии ключа создать его в WEDX → Питание → Настройки.
2. Открыть актуальную ссылку iCloud в Safari, добавить «WEDX — Здоровье» и вставить ключ при установке.
3. Запустить на разблокированном iPhone. Разрешить чтение пищевой энергии, белка, углеводов, общего жира и активной энергии, затем передачу итогов в свой WEDX.
4. Дождаться уведомления «Дней обновлено». Открыть WEDX → Питание и сверить сегодняшний день с пятью соответствующими показателями «Здоровья». При ошибке сохранить точный текст уведомления. Не переключать автоматизацию до успешной проверки.
5. «Команды» → «Автоматизация» → «Когда закрывается YAZIO» → действие запуска команды: **«WEDX — Здоровье»**; режим **«Запускать немедленно»**.
6. После проверки удалить прежние «WEDX — питание», «питание 2», «питание 3», «питание 4» и тестовые WEDX-команды. Оставить одну рабочую команду и одну автоматизацию. Чужие команды не удалять.

В WEDX уже сохранённая дневная норма применяется с её даты. Новая настройка не меняет прошлые дни. WEDX получает обновления при открытии и каждые 15 секунд на переднем плане. Автоматизация iPhone не означает непрерывную фоновую синхронизацию: если YAZIO ещё не записал изменения в Health или iOS не дал выполнить команду, повторить запуск на разблокированном телефоне.

## Передача дневных итогов

Пять Find Health Samples используют `WFHKSampleFilteringGroupBy: Day`, `WFHKSampleFilteringFillMissing: false`, без лимита результатов. Запрашиваются последние 8 суток, принимаются календарные даты от сегодня минус 7 дней до сегодня. Дополнительный крайний день не импортируется, чтобы не перезаписать старейший день частичной суммой.

Обрабатываются **сгруппированные дневные результаты**, а не тысячи отдельных интервалов активности. Не выполняется собственное сложение записей разных трекеров. Источник питания теперь Apple Health со всеми доступными ему данными, а не исключительно записи приложения YAZIO. Первоначальная сверка на реальном iPhone нужна: Mac не исполняет Health-действия, а наличие группировки само по себе не доказывает совпадение с экраном Health или YAZIO.

Отсутствие записей не заполняется нулями. День без калорий или белка пропускается, прежние данные сохраняются. Отсутствующие жиры/углеводы не стирают прошлые значения; время каждого показателя видно на экране. Отсутствующий расход явно становится неизвестным, зависимый остаток тоже неизвестен. Явный ноль допускается. Полностью удалённый дневник автоматически не обнуляет старый импорт.

## Контракт V4

`POST https://<project-ref>.supabase.co/functions/v1/health-import`, заголовки `Content-Type: application/json`, `Authorization: Bearer wedx_<token>`.

```json
{
  "version": 4,
  "source": "apple-health",
  "aggregation": "day",
  "startDate": "2026-10-16",
  "endDate": "2026-10-23",
  "energyTotals": [{"date":"2026-10-23","value":1321,"unit":"kcal"}],
  "proteinTotals": [{"date":"2026-10-23","value":58,"unit":"g"}],
  "carbsTotals": [{"date":"2026-10-23","value":121,"unit":"g"}],
  "fatTotals": [{"date":"2026-10-23","value":70,"unit":"g"}],
  "activityTotals": [{"date":"2026-10-23","value":90,"unit":"kcal"}]
}
```

Числа иллюстрируют формат, не рекомендуют питание. Один итог на дату на показатель. Повторяющиеся даты отклоняются целиком, не суммируются. До 31 принятого дня и 32 входящих итогов на показатель (с дополнительным крайним днём). Проверяются диапазоны, календарные даты, единицы и конечность чисел; значения нормализуются в ккал/г с точностью 0.001. HealthKit `Cal` (большая калория) и Foundation `kCal` принимаются как ккал; `cal` с маленькой буквы остаётся 0.001 ккал. Регистр не меняется, чтобы не внести ошибку в 1000 раз. При невалидном поле уведомление указывает показатель, поле и единицу, не раскрывая запрос или ключ.

В БД сохранён исторический ключ `source = yazio:apple-health`, чтобы обновлять прежнюю строку дня без дублей. **Происхождение V4 задаётся отдельно: `nutrition_origin = apple-health`, `activity_status = health_total`.** Старые версии используют `nutrition_origin = yazio`; прежние проверки raw-активности остаются совместимыми. Статус `health_total` означает результат группировки Health, а не независимую проверку медицинской точности.

Сохраняются только дневные итоги. Повторный импорт заменяет день, не прибавляет к нему; каждый запуск получает новый UUID. Токен хранится на сервере как SHA-256 и даёт только право импорта питания. RLS, ограничение частоты, защита владельцев и совместимость V1–V3 сохранены. Старые команды не стирают новые макросы, но могут вернуть питание к данным только YAZIO, поэтому после перехода их следует удалить.

## Генератор и проверка

```sh
python3 scripts/build-health-shortcut.py --output .local/health-daily.wflow
shortcuts sign -m anyone -i .local/health-daily.wflow -o 'public/shortcuts/WEDX — Здоровье.shortcut'
npm run check
```

Публичный шаблон содержит заполнитель ключа, не личный ключ. `--token-file` разрешён только для игнорируемой `.local/`. `--mock` заменяет Health синтетическими дневными итогами и ничего не отправляет.

Критичные параметры: числовые значения словаря — `WFItemType: 3`; HTTP File body — прямой `WFTextTokenAttachment` в `WFRequestVariable`. Встроенная группировка должна оставаться `Day`; при ошибке сервер отклонит повторяющиеся даты вместо сложения.

23.10.2026: подписанный шаблон успешно импортирован на Mac, проверен вопрос о ключе и опубликован с заполнителем. Автоматические тесты проверяют контракт, миграцию, повторы, исправления, пропуски, единицы, RLS и семь полей интерфейса. Реальное выполнение Health-запросов и совпадение цифр требуют запуска пользователем на iPhone.
